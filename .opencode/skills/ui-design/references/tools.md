# 操作型工具與資料介面

從使用者此刻要比較的維度、要辨認的對象與要處理的狀態，決定畫面的尺度與空間。

## 任務決定結構

- **比較與查找不同。** 同欄比較需要穩定對齊與短距離掃讀；查找單一對象需要名稱、識別與搜尋。工作同時包含全體查詢與當前候選判斷時，讓候選與其限制能並讀，同時保留完整資料的可達性。不要把兩種任務壓成同一張無差別長表，也不要拆散需要橫比的資料。
- **資料庫的一欄不必是畫面的一欄。** 不需獨立排序的識別資料可以合成有主次的單元，把空間留給真正要比的差異。若操作者要依某欄批次處理（例如依城市分派），它仍需對齊並能排序。
- **群組要有理由。** 異常、進行中的工作或候選集合可以成為重心；全體清單本身就是比較對象時，穩定表頭、對齊和列節奏就能承擔構圖，不需要背景圖、口號或額外統計。
- **Dashboard 首屏給能判斷與行動的狀態。** 移除沒有決策價值的 badge、統計與活動區塊。熟手處理異常時先見異常與處理入口，同時保留全體查詢。

## 空間與語意

- **按內容分配空間。** 以正常閱讀尺寸看最重要的數字、規格與識別資訊。每列大片空白而要看的資料很小時，加 row padding 不會變好；調欄位比例、行內分組與文字尺度。密集比較時過度放大會增加往返，逐件深入時獨立單元可能更清楚。
- **欄名不決定語意重量。** 同在「備註」的內容可能是普通規格、資格限制或未知時效，不能一律警示色；真正的限制也不能因欄名叫備註就淡化。狀態文字與操作可用性須對應事實。
- **操作的權重。** 最重要的操作容易找，相關的並列操作可以共存，不硬性限定一頁一個主按鈕。低頻與進階選項可以收合；當下決策必需的限制、價格與錯誤不可藏。
- **容器選擇。** modal 適合短而封閉的工作；需要閱讀、比較或回到上一步的長流程，考慮專頁、drawer 或 split view。

例：承辦人比較場地的容量、設備與空檔。一欄一筆很容易整齊，卻可能讓長地址成為視覺主體，要比的資訊落在遠處小字。可把識別資料合成一個單元，讓容量與空檔相鄰。若還要判斷出入口是否適合輪椅，相關照片要看得清高差並連到真實限制，不在每筆資料上加通用建築 icon。

## 兩個尺度都看

正常尺寸讀字並完成一次比較；完整頁看重心與節奏。窄螢幕重排時維持欄位意義、單位、選取與候選關係。驗證時從入口實際走到完成，確認必要資訊、資料關係、鍵盤路徑與功能仍在。只有桌機縮圖看來整齊，不算完成資料介面的設計判斷。
