# 渲染後評審

從實際畫面找出最影響品質的問題，連到使用者要看見與完成的事情。

## 取得有效畫面

- 同一輪取得桌機（約 1440 寬）與窄螢幕（約 390 寬）的完整頁面。等字型載入、進場動畫結束，避免把動畫途中的隱藏當成缺失。
- 保留改前畫面，修改後只重拍受影響範圍。
- 先看圖形成自己的判斷，再看 [render-check.mjs](../scripts/render-check.mjs) 或其他檢查器的輸出；機械結果會錨定判斷。

## 看什麼

先整體，再細節：

- **尺度與視線**：主體是否足以承擔頁面？資訊密度有沒有主次？
- **素材**：對照原圖與呈現。主體是否被白霧、暗幕、過小容器或裁切消掉？文字與圖像是否爭位？必要時改文字位置與構圖，而不是加重 overlay。
- **節奏**：往下是否仍推進理解，還是標題、圖示、說明反覆歸零？
- **字體**：看起來像選過的，還是未處理的預設？長中文標題與數字是否成立？
- **工具頁**：欄位比例、掃讀節奏、操作與資料的關係；不以表格整齊判定完成。
- **文字**：套用 SKILL.md 的介面文字規則，並追到共用元件與範例呼叫。
- **硬邊界**：keyboard、focus、對比、窄螢幕、適用的 light/dark；動畫清理 timer、observer 與 listener。

判斷來源時，區分規則要求、元件預設、例子暗示與實作自行補出的習慣；不能看到熟悉外型就宣稱某項規則造成。

## 用反證挑戰第一稿

拿掉新增的口號與重述句，內容是否仍完整？若圖片只是填容器，哪個可見主體其實決定了版面？若規格看不清，把它稱為 metadata 並不能合理化。「比舊稿乾淨」回答不了完成度時，用 [approved-references.md](approved-references.md) 對照實際作品。補文的資訊增益與圖形、字體、環境的美術價值分開判斷，文案刪除檢驗不是裝飾禁令。

## 上限與回報

一輪完整檢視，修正，再一輪確認受影響範圍，就停止。若還需要更多輪，通常是方向問題：回到 [direction.md](direction.md) 或向使用者說明，而不是繼續微調。

分開回報理解、操作、構圖與美術完成度，指出退步與剩餘缺陷。只宣稱證據支持的範圍：「三項修正已在畫面確認」可以，「沒有剩餘問題」不行。承擔身份辨識的頁面，可請一個沒有本次對話脈絡的 reviewer 只看截圖與 brief，避免繼承自己的框架。視覺 review 是 agent 證據，不是使用者接受。
