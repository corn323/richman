# 使用者已肯定的作品

以下三站是 TinyYana 明確確認喜歡的品質參考。個站從 Fuwari 修改發展而來，兩者是同一 lineage，不算兩份獨立偏好；masterpiece 是另一種品質依據。這些是有條件的觀察，不是 house style：使用時要看實際畫面，本文、CSS、色票或縮圖不能代替觀看。轉譯方法見 [direction.md](direction.md)。

## TinyYana 個站：環境與閱讀表面

[網站](https://www.tinyyana.com/)、[原始碼 c865092](https://github.com/TinyYana/tinyyana-web/tree/c8650921a60aa88c07f406aebf6790ef9f68fb89)。

首頁的夜空不是平均鋪在內容後面的裝飾：左上枝條、右上月亮與左側姓名留下觀看空間，明亮的主內容與人物側欄跨過天空下緣，讓讀者從環境進入閱讀。內頁天空縮短，正文提早出現，仍保留同一環境。窄版側欄退出首屏，背景與內容的交界保留，不是把桌機等比縮小。

- **可移用的關係**：背景承擔情緒和空間，面板承擔閱讀；交界的覆蓋、明暗與對齊把兩者接起來。卡片、漸層和圓角在這裡有美術價值，不能只因它們沒有新增資訊便刪除。若自己的圖是證據或作品，先確定交界不遮住主體。
- **字體**：姓名、中文標題與正文的柔和筆觸延伸人物性格，正文以足夠行距承載長文，程式字串另用等寬字（實作為霞鶩文楷 TC 與 JetBrains Mono）。成立的是字樣與內容氣質的協調，不是指定別的專案裝同一字型；高頻掃讀的工具未必適合全文手寫感。
- **成立條件**：個人內容與角色身份有連結；環境能在不同頁面退讓；表面、文字與邊界的色性協調。不可整套搬走夜櫻、紫粉色、人物側欄、花朵標記或文案。

## Fuwari：高細節圖片不用充當文字底板

[官方 demo](https://fuwari.vercel.app/)、[原始專案](https://github.com/saicaca/fuwari)。

桌機的背影、城市與鳥群保有完整觀看區，導覽和文章在獨立的亮表面上，第一列卡片跨過 banner 下緣。窄版縮短景觀，保留背影與城市，文章提早接續，個人側欄不擠在最前面。

- **移用**：高細節圖沒有足夠負空間時，把長文字移到閱讀表面，用位置、尺度和共同邊界連接，不必把整張圖壓暗。先看主體與環境還剩多少，再決定容器尺寸。
- **同源比較**：個站保留了環境進入閱讀表面的交界，卻依作者意圖重排權重：側欄移到右側讓姓名與主內容接續，景觀改成有留白的夜空以承載介紹，首頁以作品／筆記／現在／關於導覽，而不沿用 Fuwari 的文章索引權重、粗黑標題、左側色線與整條箭頭入口。可移用的是按目的重分空間的判斷，不是「banner + sidebar + floating card」或固定色票。
- **條件**：需要可橫向裁切且主體位置明確的素材；多個重要主體散佈全圖時，可能應保留全幅並提供放大。它是文章列表，不移用到工具的整個骨架。示範插畫不可移植。

## masterpiece：選擇性弱化讓焦點更清楚

[2024 年活動網站](https://5th.uishigure.com/masterpiece/)。

人物從畫框伸手，臉、手與框的輪廓清楚，周圍較淡、較模糊的前景建立觀看距離。主視覺淡出到標題與日期的閱讀區，字形的粗細與伸展也是構圖的一部分。先讓人觀看角色，再進入活動資訊；吸引觀看本身承擔活動目標。

- **移用**：先決定清楚的是誰、退後的是誰，再選局部淡化或景深，並檢查臉、產品細節或操作證據是否因此更突出。這不是禁止模糊，也不能替全幅白幕辯護。
- **條件**：依賴為主視覺準備的高品質素材、前後景與閱讀空間。普通截圖沒有可分離的角色時，不假造人物出框。紅白色、花形選單、英文細標與雙語副標不移入通用 UI；官方角色與插畫不複製。

## 放回自己的頁面

用自己的內容指出一個有理由的主要關係改變，例如「訪客要先判斷作品，正文從作品中央移到下緣，作品取得足夠觀看尺度，下一段沿同一邊界接入」，再以原頁、修改後的正常尺寸、窄版與段落接續核對。對照這些作品的整體完成度：自己的字體是否仍像未選過的預設？素材是否只是填框？下半頁是否退回無關的同重區塊？「比舊稿好」不能代替品質目標，也不能代替 TinyYana 接受。
