# 視覺層級、色彩與狀態

## 層級從判斷出發

先問使用者要辨認哪個對象、判斷哪個差異，再安排視覺重量。文件的 h1/h2 等級不等於畫面的字級；頁名可能只是定位，主要資料或作品才是主體。

重量來自面積、位置、字面、字重、色彩對比與孤立程度。只用字級建立層級，容易得到過大的頁名與過小的資料。先用實際字體找到能舒適閱讀的資料尺寸，再讓名稱、數字或選取狀態在周圍形成差異。

- **降權**適合「旁邊的東西在搶注意力」：減少那些元素的飽和、粗細或背景重量。主體因欄寬、位置或比例失當而弱時，降權修不好；整頁已經淡而零碎時，不要再把次要字染灰。規格、時間與限制常是決策核心，不能一路縮小淡化。
- **操作**依當下重要性給重量，不把所有按鈕按「成功綠、危險紅」塗滿。危險行為的名稱與後果仍要清楚；視覺次要不等於藏起來。
- **Panel** 的邊框、底色、色線與陰影都是額外注意力，應標出有意義的分組、可操作對象或浮層，而不是讓每段說明都顯得重要。常設條件可以靠位置與可讀文字連到操作；真正需要中斷的錯誤才提高顯著程度。拿掉框後關係不清，先修位置和群組，再決定是否需要邊界。TinyYana 已否定把淡底加左側色線當作預設提示樣式。

## 色彩

沿用既有色彩角色；需要補色階時依實際文字、背景、border 與互動狀態補足，不硬建固定階數或指定色相。HSL 便於推理色相，OKLCH 便於調整感知亮度；用專案已有的格式。

- 改變亮度不等於達到對比，light/dark 各自在真實背景量測，透明材質也計入。彩底白字對比不足時可改淡底深字。
- success、error、warning 同時有文字或其他可辨識訊號；hover/active 不靠難以分辨的細微色差表達狀態。
