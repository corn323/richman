# 使用體驗

從實際使用者與目標出發：他從哪裡進來、知道什麼、要完成什麼、失敗後如何回來。

- 操作前能預期結果、成本與影響範圍；操作後看得到成功、進行中或失敗。
- 狀態由使用情境決定：真的沒有資料、搜尋無結果、已有內容但尚未選取是不同情境。待選的詳情區不套零資料的鼓勵段落。成功要對應真正完成的範圍：排入佇列不代表處理完畢，本地示範不代表正式結果。
- 錯誤說明問題與下一步，保留輸入，避免重走整段流程；重試不造成重複付款或發送。
- 常用路徑直接，低頻與進階選項按需展開；當下決策必需的限制與價格不藏。確認只放在真正需要決定或難以復原的動作。
- 命令、UI、文件使用相同名稱與行為；不把實作理由塞進產品文案。介面文字依 [ui-design 的介面文字](../ui-design/SKILL.md#介面文字)，先修命名、分組與操作線索，不以多寫教學彌補難懂的流程。
- 鍵盤、輔助科技與背景知識較少的使用者都能到達重要功能。

按問題深入：整段流程看 [review-framework.md](references/review-framework.md)；表單、狀態、權限、CLI 與設定看 [states-and-components.md](references/states-and-components.md)；容易漏掉的問題看 [checklist-and-antipatterns.md](references/checklist-and-antipatterns.md)。小修不需全讀。

驗證從入口走到成功，再走一條相關的失敗路徑。報告實際卡點與結果，不套固定診斷模板；未實際操作時不宣稱體驗已證明。
