# 資訊設計

讓讀者用最少必要資訊理解事情、做出決定或開始工作。

從讀者現在知道什麼、要回答什麼、答完能做什麼開始。把原文當材料，辨認對象、關係、證據與限制，再決定承載它們的結構。網站不是先列 hero、功能卡與 CTA 再填文案。

- 比較選項需要相同尺度與相鄰證據；追查一筆記錄需要識別、狀態與歷程；判斷作品需要看見作品及理解它的背景；故事或過程需要能追蹤的因果與時間。依關係安排並列、連續或深入閱讀，不把每種關係都翻成同重量的區塊。
- 閱讀順序由情境決定。熟手處理異常時先見異常與操作；陌生訪客可能先需要作品或實例才能理解產品。「先講結果」不等於每個首頁都是大標加摘要。
- 決策必需的費用、限制與資料時效留在決策位置；背景與低頻細節延後。合併重複、刪除無用文字，不靠隱藏必要資訊減少畫面。
- brief 的列舉不等於 section 數量。先判斷幾點是否共同回答同一問題；若只是同一玩法或服務的條件，直接命名或留在相關材料旁，不把每點擴寫成一組標題、故事與 badge。每段都是圖示、標題、說明時，檢查它們是否真的同類等權；一張作品可以承擔多項說明，相同任務的重複則是功能，不必為反模板製造變化。
- 文字長度、資料量與圖片本身會改變結構。在真實內容中測試閱讀路徑，不只看標題大綱。

介面上的標題、按鈕、提示與空狀態文字，遵守 [ui-design 的介面文字](../ui-design/SKILL.md#介面文字)。版面與視覺在 ui-design 處理；文字編排不等於美術完成。

Agent 指引：入口說清目標、真正的邊界、檔案位置與載入時機。保留會改變判斷的條件、取捨與失敗例；模型已會的一般知識不重寫；相同規則只維護一份，其他地方連結它。

讀回成品：新讀者是否找得到第一步、限制與更深的資料？重要主張有證據嗎？刪減是否迫使讀者猜必要條件？
